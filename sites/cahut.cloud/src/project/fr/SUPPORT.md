# Obtenir de l'aide

Trois endroits, dans cet ordre :

1. **La documentation**, sur [docs.cahut.cloud](https://docs.cahut.cloud) : installer, brancher une IA, les concepts, l'administration, et la référence de chaque opération et de chaque commande.
2. **Les Discussions**, dans *Q&A* : posez votre question là. D'autres utilisateurs répondent, et le mainteneur passe une fois par semaine.
3. **Un ticket**, pour un bug que vous pouvez reproduire, avec le formulaire de rapport de bug.

Il n'y a pas de support par e-mail ni par message privé, et pas de délai de réponse garanti. Cahut est maintenu par une seule personne, dans à peu près un créneau par semaine. Les seules adresses privées sont `security@cahut.cloud` pour les failles ([SECURITY.md](SECURITY.md)), `conduct@cahut.cloud` pour le [code de conduite](CODE_OF_CONDUCT.md), et `contact@cahut.cloud` pour le nom et les partenariats ([TRADEMARK.md](TRADEMARK.md)). Aucune ne fait de support.

## Bien demander

Donnez :

- la version, celle de `cahut version` ;
- le système : AlmaLinux ou Ubuntu, et sa version ;
- comment Cahut a été installé : `install.sh`, une archive de release, ou `make dev` sur votre machine ;
- le client d'IA avec lequel vous vous connectez, s'il joue un rôle ;
- ce que vous attendiez, et ce qui s'est passé ;
- les lignes du Logbook qui vont avec, celles de `cahut logbook`, sans aucun jeton ni mot de passe.

## À quoi s'attendre

Chaque nouveau ticket reçoit une réponse dans la semaine : confirmé, besoin de précisions, doublon, hors périmètre, ou accepté et placé dans un jalon. Ce n'est pas une promesse de correction. Un ticket qui attend des précisions depuis trente jours est fermé, et se rouvre d'un commentaire. Un bug confirmé n'est jamais fermé pour inactivité.

Un support payant pour les organisations viendra peut-être après la version 1.0. Il ne viendra jamais au détriment des réponses publiques.
